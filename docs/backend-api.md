# Backend API client

`ELIFE_Api` is the mod's REST client, wrapping Enfusion's `RestApi` to talk to the
Bridge (the local, unauthenticated proxy the gameserver runs alongside itself — never
the Central API directly).

## Setup

### Workbench (local dev)

No setup needed — defaults to `http://127.0.0.1:5200/` if no config file exists.

Only create `$profile:ELifeRPG.json` if you need to point at something other than a
locally-running Bridge:

```json
{
  "serverUrl": "http://127.0.0.1:5200/"
}
```

- Workbench profile folder: `Documents/My Games/ArmaReforgerWorkbench/profile/`

### Production / dedicated server

- **The config file is required.** No fallback — the server refuses to start
  (`GetGame().RequestClose()`) if it's missing or `serverUrl` is empty.
- Pin the profile directory explicitly with the `-profile <path>` startup parameter
  rather than relying on platform defaults — makes the deployment predictable and
  easy to back up.
- Place `ELifeRPG.json` (same format as above) at `<profile path>/ELifeRPG.json`,
  pointed at the real Bridge URL for that environment.
- On startup the server also checks the Bridge is actually reachable — retries 5x,
  2s apart, then refuses to start if it still can't connect. Workbench only logs a
  warning for the same check and keeps running (see `ELIFE_GameMode.OnGameStart()`).

## The generated client

Everything under `src/Scripts/Game/Core/Api/` except `ELIFE_Api_Base.c` is generated by
[enfusion-codegen](https://github.com/ELifeRPG/enfusion-codegen) from the Bridge's OpenAPI
document. **Don't edit those files** — the next run overwrites them. Regenerate with the
Bridge running:

```sh
enfusion-codegen generate http://127.0.0.1:5200/openapi/v1.json \
  --output src/Scripts/Game/Core --prefix ELIFE_
```

- `Api/ELIFE_Api_<Tag>.c` — one method per endpoint on `ELIFE_Api`.
- `Api/Structs/` — request/response structs (`JsonApiStruct`) and enums.
- `Api/Callbacks/` — one callback per response type, parsing the body into its struct.
- `Api/ELIFE_BaseRestCallback.c` — the shared callback base.
- `Api/ELIFE_Api_Base.c` — scaffolded once, then hand-maintained (config, `GetElifeApi()`).

## Using it in new features

```c
class MyFeatureComponent : ScriptComponent
{
    //! Only needed to read the HTTP code in the handler.
    protected ref ELIFE_SavedContactCallback m_SaveCallback;

    void Save(string phoneId, string number, string name)
    {
        ELIFE_SavePhoneContactRequest request = new ELIFE_SavePhoneContactRequest();
        request.number = number;
        request.displayName = name;

        m_SaveCallback = ELIFE_Api.GetInstance().SavePhoneContact(request, phoneId, this, "OnSaved");
    }

    void OnSaved(ELIFE_EApiStatusCode status, JsonApiStruct data, string phoneId)
    {
        ELIFE_SavedContact saved = ELIFE_SavedContact.Cast(data);
        int httpCode = m_SaveCallback.GetHttpCode();
    }
}
```

- **Handler signature:** `(ELIFE_EApiStatusCode status, JsonApiStruct data)`, plus a
  trailing `string` when the route's first path parameter is a string — that value
  (e.g. the `phoneId`) is passed back. The arity must match, or the call fails.
- **The handler must be public** — a protected/private target throws a VM exception
  once a response actually arrives.
- **Callback lifetime is handled for you:** the base callback keeps itself alive until
  its response arrives. Keep the returned callback only if you need `GetHttpCode()`;
  every failure reaches the handler as `ELIFE_EApiStatusCode.ERROR` either way, and is
  logged with its HTTP code.
- **Request bodies** are the generated `*Request` structs — fill the fields, the method
  packs them. Never build JSON by hand; `Pack()` escapes strings.
- **Empty string query parameters are left out** of the URL, so pass `""` for an
  optional one you don't want to send.

### Adding behaviour to a generated struct

Use a `modded class` in the feature's own folder, never the generated file — e.g.
`Features/Phone/Api/ELIFE_MessageThreadUpdate_Phone.c` adds `Copy()`/`Redact()` and a
`displayName` field to `ELIFE_MessageThreadUpdate`.

### Bare-array responses

Generated `List*` methods for endpoints returning a **bare JSON array** don't parse the
body (`JsonApiStruct` only parses objects) — the handler gets `null` data. Still call the
generated method, keep the returned callback, and read the raw body with `GetData()` in
the handler, wrapping the array in an object yourself — see
`ELIFE_PhoneRawDto.ExpandFromArray()` and `ELIFE_PhoneGadgetComponent.OnListFetched()`.

### Engine quirks worth knowing

- **Bools are packed as `1`/`0`**, not `true`/`false`. The Bridge accepts both; anything
  else talking to the mod's requests would need to as well.
- **Don't re-`Pack()` a struct filled by `ExpandFromRAW()`** — it logs
  "JsonApiStruct :: Operation called twice". Pass on the raw response text, or copy into
  a fresh struct first (see `ELIFE_MessageUpdates.MergedWith()`).
